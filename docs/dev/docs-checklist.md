# 문서 갱신 체크리스트

> 코드(`Source/` · `Config/` · `Scripts/` · 에셋)를 바꾼 세션은 **합치기 전에** 이 표를 훑고 해당 문서를 고친다. 문서가 코드와 다르면 문서를 코드에 맞춘다(CLAUDE.md). 메인 세션은 합칠 때 이 표가 지켜졌는지 본다.

## 바꾼 것 → 고칠 문서

| 바꾼 것 | 고칠 문서 |
|---|---|
| 새 클래스 · 컴포넌트 · 서브시스템 | 그 시스템 문서(`docs/systems/<시스템>.md`)의 해당 절에 「구현: `Source/Grimoire/<폴더>/<파일>.h` 의 `UGrim…`」. 새 폴더면 [아키텍처 개요](../systems/)의 「모듈 · 폴더 구성」 표 |
| 클래스 · 파일 이름 바꾸기 · 지우기 | 옛 이름을 쓰는 문서 전부(`grep -rn 옛이름 docs`). 결정 기록(`decisions.md`)의 옛 이름은 그대로 둔다 |
| 콘솔 명령 · 치트 · 콘솔 변수 | [테스트 치트](./cheats) 표 + 그 시스템 문서의 「콘솔 · 확인」 |
| `Config/Default*.ini` 섹션 · 키 | 그 시스템 문서에 섹션 이름 · 키 · 기본값 한 줄 |
| 데이터 표(CSV · DataTable · DataAsset) · 에셋 경로 | 그 시스템 문서의 데이터 절. 만드는 스크립트가 있으면 `Scripts/...` 경로도 |
| 새 확인 스크립트 · 자동화 테스트 묶음 | 그 시스템 문서의 「확인」 절(테스트 이름 `Grimoire.<시스템>.*`) |
| 스펙과 다르게 만든 것 · 새 결정 | 먼저 스펙(`docs/spec/`)을 고치고 [결정 기록](../spec/decisions)에 한 줄. 정할 수 없으면 미결 질문 Q 번호로 |
| 계획 문서의 갈래를 마침 | 그 계획 문서(`docs/systems/m*-plan.md`)의 「통합 결과」 — 합친 커밋 · 고친 것 · 확인 · 사람 눈으로 볼 것 · 남은 것 |
| 마일스톤 상태가 바뀜 | [로드맵](../systems/roadmap) 표의 상태 칸 |
| 밟은 함정 · 쓴 도구 | 그 시스템 문서의 「함정」 절, 모든 세션에 해당하면 CLAUDE.md 「규칙과 함정」(80줄 안) |
| 무엇이든 합침 | [개발 기록](./history)에 한 줄 — 날짜 · 무엇을 · 어떻게 · 어디에 · 합치기 커밋 |
| 새 문서 페이지 | `docs/.vitepress/config.mts` 의 sidebar 에 한 줄 |

## 적는 법

- 코드 위치는 **저장소 루트 기준 전체 경로**를 백틱 안에: `` `Source/Grimoire/Magic/GrimSpellAbility.h` ``. 폴더는 끝에 `/`. 에셋은 확장자 없이 `` `Content/Grimoire/Maps/L_Tower` ``.
- 절 전체가 아직 없는 설계면 머리 바로 아래에 `> 상태: **계획(M6)** — 코드 없음.` 처럼 적는다.
- 아직 없는 것(설계안)을 적는 줄에는 「계획」 · 「미구현」 · 「예정」 중 하나를 쓴다 — 검사 스크립트가 그 줄은 건너뛴다.
- 수치는 문서에 옮겨 적기보다 데이터 위치(ini 키 · CSV)를 가리킨다. 옮겨 적었다면 데이터를 바꿀 때 같이 고친다.

## 검사

```bash
npm run docs:check      # 문서에 적힌 경로 · 콘솔 명령이 실제로 있는지(오류면 실패)
npm run docs:build      # 깨진 링크 검사
```

- `docs:check` 는 `Scripts/Docs/check_docs.mjs` 다. `docs/**/*.md` 의 인라인 코드에서
  1. `Source/` · `Config/` · `Scripts/` · `Content/` · `art/` 로 시작하는 경로가 있는지(**오류**, `*` 는 앞 폴더만 본다, `art/**/raw/` 는 건너뜀),
  2. 「Grim.시스템.명령」과 `GrimSuperCheat 1` 같은 콘솔 명령이 Source 에 등록돼 있는지(`TEXT("Grim.…")` · `UFUNCTION(Exec)`, **오류**),
  3. 「UGrim이름」 · 「Grim이름」 식별자가 Source · Config 어딘가에 있는지(**경고** — 설계 문서는 아직 없는 클래스를 적으므로. `--strict` 면 오류)
  를 본다. 줄에 「계획」「미구현」「설계안」「예정」「옛 이름」이 있으면 건너뛰고, 절 머리에 그 낱말이 있거나 머리 바로 아래 `> 상태:` 줄이 계획이면 그 절 전체를 건너뛴다. 레벨에 놓인 액터 이름(`GrimCandle_2` 처럼 `_숫자`)은 보지 않고, 결정 기록도 보지 않는다.
- 경고 목록은 「아직 안 만든 설계」의 목록이기도 하다 — 만들면 그 줄의 상태를 「구현」으로 바꾼다.
