# 성능 예산 · 최적화 규칙

최적화는 끝에 몰아서 하지 않는다. 이 문서는 **목표 사양 · 프레임 예산 · 시스템별 예산**과 **모든 세션이 지킬 규칙**,
그리고 **측정 기록 · 다음 할 일**을 한곳에 둔다. 측정 절차는 [성능 측정 방법](../dev/perf-measure).
수치는 2026-11-06 첫 제안(「제안」 — [결정 기록](../spec/decisions)), 측정이 쌓이면 고친다.

## 목표 사양 · 프레임 예산

| | 최소(Low) | 권장(High) — **예산 기준** | 개발 PC(측정용) |
|---|---|---|---|
| GPU | RTX 2060 · RX 5600 XT (6 GB) | RTX 3060 · RX 6600 XT (8 GB) | RX 9070 (16 GB) |
| CPU | 6코어 Zen 2 · i5-10400 | 6코어 Zen 3 · i5-12400 | Ryzen 5 9600X |
| RAM | 16 GB | 16 GB | 31 GB |
| 해상도 · 품질 | 1080p, 확장성 Low, TSR 50 % | 1080p, 확장성 High, TSR 67 % | 1080p Epic(기본값 그대로) |
| 목표 | 30 fps 바닥(33.3 ms) | **60 fps(16.6 ms)**, 끊김 없는 30 fps 바닥 | — |

- DX12 · SM6 만(Nanite · 가상 섀도 맵 · Lumen 필요). 저장소 설정 그대로.
- **개발 PC 환산**: RX 9070 은 권장 GPU 의 약 2.2배 → 개발 PC 1080p Epic 에서 **GPU 7 ms 이하**면 권장 사양 High 60 fps 안쪽으로 본다.
  CPU 는 9600X 가 권장의 약 1.5배 → 개발 PC 게임 스레드 **7 ms 이하**(에디터 바이너리는 여기에 +30 % 쯤 무겁다).
- 끊김: p95 프레임이 예산의 1.5배를 넘지 않는다. 스트리밍 · 셰이더 컴파일 끊김(33 ms 초과)은 이동 1분에 1번 이하.

## 모든 세션이 지킬 규칙

새 시스템 · 에셋을 넣을 때 이 목록을 본다. 어기면 이유를 그 시스템 문서에 적는다.

### 메시 · 텍스처

1. **정적 메시는 Nanite** — 불투명 · 마스크드 모두(폴리지 포함). 예외: 반투명, 아주 작은 UI 용 메시. 자체 제작 에셋은
   `Scripts/Environment/import_env_asset.py` 가 Nanite 를 켠다. Nanite 메시는 LOD 를 따로 만들지 않는다(폴백 메시는 기본값).
2. 엔진 기본 도형(`/Engine/BasicShapes`)은 Nanite 가 아니다 — 그레이박스 · 임시 몸에만 쓰고, 많이 늘어놓을 땐 **인스턴스(ISM/HISM)** 로.
3. 텍스처는 2의 거듭제곱, 밉 있음, 압축(BC). 소품 2K · 큰 것 4K 까지, 그 이상은 가상 텍스처. 노멀 · ORM 은 합쳐서(채널 묶기).
4. 머티리얼: World Position Offset(바람 흔들림)은 `WPO Disable Distance` 를 준다(Nanite 그림자 캐시가 깨진다). 픽셀 깊이 오프셋 · 테셀레이션 쓰지 않는다.

### 월드 · 스트리밍

5. **World Partition**: 셀 256 m, 로딩 거리 512 m(지형 1차 그대로). 10 × 10 km 에서도 같은 격자.
6. **늘 로드(공간 로드 끔)는 전역 액터만** — 하늘 · 날씨 · 기후 볼륨 · 시작 자리 · 표식. 건물 · 소품 · 그레이박스는 공간 로드 + HLOD.
7. 공간 로드 되는 것은 **HLOD 층**에 든다: 건물 · 바위 = `HLODLayer_Merged`, 반복 소품 = `HLODLayer_Instanced`. HLOD 빌드는 지형 · 배치를 바꾼 세션이 돌린다.
8. 던전 · 실내는 데이터 레이어 또는 레벨 인스턴스(월드 · 멀티 문서).
9. **동기 로드 금지**(게임 중 `LoadObject` · `TSoftObjectPtr::LoadSynchronous`) — 생성자 · 시작 시 한 번은 괜찮다. 런타임은 `FStreamableManager` 비동기.

### 폴리지 · 풀

10. 사라지는 거리(끝 컬 거리) 상한: 풀 50 m, 덤불 · 꽃 120 m, 바위 200 m, 나무 400 m(그 너머는 HLOD · 원경 메시). 시작 컬은 끝의 70 %.
11. 그림자: 나무 · 큰 바위만. 풀 · 덤불 · 작은 돌은 그림자 끔. 풀은 충돌 끔.
12. 풀 밀도: 랜드스케이프 그래스 1 m² 당 20 이하(Low 는 `grass.DensityScale 0.5`). 폴리지 인스턴스는 256 m 셀 하나에 20,000 이하.

### 틱 · CPU

13. **틱은 기본 끔** (`bCanEverTick = false`). 필요한 것은 ① 타이머(0.1 ~ 1 초) ② 틱 간격(`TickInterval`) ③ 이벤트 순으로 찾는다.
14. 매 프레임 틱이 꼭 필요하면(이동 · 카메라 · 연출) 화면 밖 · 멀리서 멈춘다: `TickWhenOffscreen` 끄기, 거리별 간격(가까이 0 · 30 m 밖 0.1 초 · 80 m 밖 끔).
15. 스켈레탈 메시: `VisibilityBasedAnimTickOption = OnlyTickPoseWhenRendered`, 생물 · NPC 는 URO(업데이트 비율 최적화) 켬.
16. 틱에서 액터 순회(`TActorIterator`) · 오버랩 · 레이 여러 개를 하지 않는다 — 서브시스템이 목록을 들고 일괄로.
17. 생물: 활성 40마리, 접힘/펼침(생태계) 유지. 멀리 있는 무리는 기록으로만 계산한다.

### 네트워크

18. 세계 사물은 **휴면**(`DORM_DormantAll`) 으로 시작하고 상태가 바뀔 때만 깨운다(`FlushNetDormancy`). 상호작용 사물 · 거점 조각 · 작물 모두.
19. `NetUpdateFrequency` 를 액터마다 정한다: 플레이어 · 탈것 60 ~ 100, 생물 10 ~ 30, 사물 1 ~ 4. `NetCullDistanceSquared` 는 생물 150 m, 사물 100 m 기본.
20. 목록은 FastArray(`FFastArraySerializer`), 매 프레임 RPC 금지, 연출은 GameplayCue · Unreliable 멀티캐스트.
21. **리슨 vs 전용**: 리슨 호스트는 렌더 + 서버를 한 스레드에 진다 — 서버 몫 4 ms 를 넘기는 기능(전체 지도 AI, 모든 사물 매 틱 갱신)은 만들지 않는다.
    전용 서버는 `-nullrhi` 처럼 그리지 않으니 연출 코드(`IsNetMode(NM_DedicatedServer)` 에서 건너뛰기)를 서버에서 돌리지 않는다.
22. 대규모(16명 넘음) 대비: 복제 그래프 · Iris 로 옮길 수 있게 관련성은 엔진 규칙(거리 · 소유)에만 기대고 특수 처리를 넣지 않는다.

### 렌더 · 연출

23. 동적 광원: 그림자 내는 점 · 스포트 광원은 화면에 4개 이하, 나머지는 그림자 끔 + `Max Draw Distance`. 모닥불 · 양초 빛은 30 m 에서 끈다.
24. **Niagara**: 모든 시스템에 Effect Type(확장성 · 거리 컬 · 중요도 예산)을 준다 — 마법 = `EFT_Grim_Spell`, 날씨 = `EFT_Grim_Weather`, 환경 = `EFT_Grim_Ambient`.
    입자 수 상한: 마법 하나 2,000, 비 · 눈 20,000(GPU 시뮬), 화면 전체 50,000. 자주 나는 이펙트는 풀링(`ENCPoolMethod::AutoRelease`).
25. 반투명은 겹침이 비싸다 — 큰 반투명 판(안개 판 · 빛줄기)은 화면에 몇 장 이하, 월드 공간 위젯(개발 글씨)은 거리 · 화면 밖에서 그리지 않는다.
26. 확장성(Scalability) 그룹은 `Config/DefaultScalability.ini`(아직 없음 — 다음 할 일 3)에서만 손댄다 — 코드에서 `r.` 변수를 직접 바꾸지 않는다(사용자 옵션이 덮인다).

## 언제 재나 · 최적화 세션

사용자가 따로 시키지 않아도 아래 시점에 잰다. 숫자는 [QA — 성능 예산](../qa/perf)의 QA-PRF 항목과 비교한다(재는 법은 [성능 측정 방법](../dev/perf-measure)).

| 언제 | 누가 | 무엇을 |
|---|---|---|
| 완료 보고 전 — 렌더 · 틱 · 스폰 · 레벨 · 에셋을 바꾼 세션 | 그 세션 | `measure.ps1 -Only Render`(약 4분). 결과를 자기 QA 에 적는다 |
| 완료 보고 전 — 복제 · RPC 를 바꾼 세션 | 그 세션 | `measure.ps1 -Only Net`(약 2.5분) |
| 큰 기능 브랜치를 `main` 에 합친 뒤 | 메인 세션 | 빌드 · 자동화 테스트와 함께 `measure.ps1`(전체), QA-PRF-001~008 결과 칸 갱신 |
| 위 측정에서 예산을 넘었을 때 | 메인 세션이 **최적화 세션을 바로** 연다 | 넘은 항목을 고치고 다시 잰다. 마일스톤 중간이어도 기다리지 않는다 |
| 마일스톤을 마칠 때 | 메인 세션이 **최적화 세션을 마무리 단계로** 연다 | 전체 측정 → 지난 기준선과 비교 → 나빠진 곳 · 「다음 할 일」 처리 → 아래 「측정 기록」에 한 절 |

- 최적화 세션은 **매번 새로 연다**(계속 열어 두지 않는다). 긴 대화는 판단을 흐리고 워크트리 생성물이 수 GB 씩 남는다. 이어서 할 일은 이 페이지의 「측정 기록」과 「다음 할 일」이 넘겨준다 — 새 세션은 이 페이지부터 읽는다.
- 프레임 시간은 같은 PC 의 다른 세션 때문에 실행마다 흔들린다. 예산 안이면 소폭 차이는 회귀로 보지 않는다. 예산 대비로 판단하고, 전후 비교는 같은 바이너리로 연달아 잰다.

### 2026-11-06 첫 측정 · 첫 최적화

개발 PC(RX 9070 · 9600X), 에디터 바이너리 `-game`, 1080p Epic, `Scripts/Perf/measure.ps1`. 같은 PC 에서 다른 세션의 게임 · 에디터가 함께 돌아
**프레임 시간은 실행마다 7 ~ 12 ms 로 흔들렸다** — 아래 전후는 같은 바이너리를 콘솔 변수로 예전 동작(`-ExtraCmds "Grim.Sky.SunRotationStep 0,Grim.DevLabels.MaxDistance 10000000"`)과 새 동작으로 연달아 잰 것이다.

**기준(최적화 전)**: door 8.1 ms(123 fps) — 게임 3.8 · 렌더 스레드 8.1 · GPU 5.9 ms, 드로 콜 720, 프리미티브 610만, 액터 1,181, 메모리 2.75 GB. 모든 자리에서 **렌더 스레드가 프레임과 같아 병목**이고,
GPU 에서는 **그림자 깊이(가상 섀도 맵) 2.0 ~ 2.7 ms** 가 가장 컸다(GPU 의 40 %). 원인: 하늘 컨트롤러가 매 프레임 해 방향을 아주 조금씩 돌려 VSM 캐시가 프레임마다 통째로 무효.

| 자리 | GPU ms 전 → 후 | 그림자 깊이 ms 전 → 후 | 보이는 개발 글씨 |
|---|---|---|---|
| door | 6.44 → 4.59 | 2.63 → 0.58 | 44 → 5 |
| path200 | 5.88 → 4.48 | 2.29 → 0.54 | 44 → 7 |
| hilltop | 5.57 → 4.27 | 2.06 → 0.58 | 44 → 7 |
| pond | 5.90 → 4.00 | 2.36 → 0.38 | 44 → 6 |
| valley | 5.37 → 4.43 | 2.04 → 0.58 | 44 → 0 |
| creatures(생물 16) | 5.40 → 4.88 | 1.91 → 0.49 | 44 → 10 |
| rain | 5.19 → 4.27 | 2.21 → 0.39 | 44 → 7 |

- 프레임당 틱 83 → 39(위젯 컴포넌트 44 → 0). 게임 스레드 `UI` 0.7 ~ 0.9 ms 는 HUD(UMG) 몫으로 남았다.
- 렌더 스레드는 여전히 7 ~ 10 ms(에디터 바이너리 · CPU 경합 포함) — 쿡한 빌드로 다시 재야 한다(다음 할 일 1).
- 생물 16마리 + 소환 12: 게임 스레드 CharacterMovement +0.34 ms(마리당 약 0.02 ms) — 예산 안.
- 네트워크(리슨 서버 + 클라이언트 1, 둘 다 60 fps 로 묶음, 연결당): 서버 → 클라이언트 가만히 2.6 · 생물 옆 5.0 · 비 3.9 kB/s, 클라이언트 → 서버 약 4 kB/s,
  패킷 약 59/s. 서버 월드 틱 1.5 ~ 2.8 ms, 관련 복제 객체 108(활성 80). **예산(평균 15 kB/s · 올림 5 kB/s) 안.** 처음 측정은 헤드리스 클라이언트가 1,000 fps 로 돌아 올림이 26 kB/s 로 부풀었다 — 측정은 반드시 프레임 제한.
  비로 바꾸는 순간 서버에 1초 멈춤 1번(다음 할 일 6).
