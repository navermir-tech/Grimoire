# 멀티플레이

> 관련 요구사항: R13(로컬 서버 멀티), R12(인스턴스 던전), R11(공용 거점)

## 방식 (R13)

- 팰월드 · 인슈라오디드와 같은 **로컬 서버** 방식. 한 사람이 서버를 띄우고 친구가 들어온다.
  - **호스트 플레이**(리슨 서버): 게임 안에서 "서버 열기" → 호스트도 함께 플레이. 1차 목표.
  - **전용 서버**(데디케이티드): 별도 실행 파일로 24시간 띄움. 2차 목표.
- 접속: 처음엔 LAN · IP 직접 입력.
- **Steam 친구 초대**(R32 확정 — Steam 출시 때): 게임 안 「친구 초대」 또는 Steam 오버레이(Shift+Tab)로 친구를 부르고, 친구는 Steam 친구 목록의 「게임 참가」로 바로 들어온다. Steam 의 접속 중계를 써서 **포트 포워딩 없이** 호스트 플레이에 붙는다. 호스트가 서버를 「친구만 · 초대만 · 공개」로 정한다(제안).
- 인원(Q11 확정): 수직 슬라이스 4명, 최대 동시 접속 8명.

### 대규모 서버 (100명 단위) — 검토 (R32, 결정 아님)

- **레퍼런스 확인**: 팰월드 전용 서버는 공식 상한이 **32명**이다(설정 `ServerPlayerMaxNum` 1~32). 100이라는 숫자는 서버 인원이 아니라 **길드 인원 상한**(1~100) 설정에서 나온 것으로 보인다. 1.0 에 서버 묶기(클러스터)로 더 큰 인원을 받는다는 글이 하나 있지만 공식 출처는 못 찾았다(불확실). → [레퍼런스 조사](./references#대규모-서버-r32)
- **엔진은 된다**: 언리얼은 100명 전용 서버 게임(포트나이트)을 만든 엔진이고, 5.x 에는 대규모 복제용 기능(복제 그래프 · Iris)이 있다. 그리모리는 이미 서버 권위 · GAS · 휴면 · FastArray 로 짜여 있어 방향은 맞다.
- **그리모리에서 무거운 것**:
  - **리슨 서버로는 안 된다** — 100명은 **전용 서버**만. 전용 서버는 소스 빌드 엔진이 필요하다(로드맵 리스크).
  - **세계 상태가 많다** — 모든 사물의 속성 상태(R16), 생태계 생물 AI(R14), 거점 조각 수천 개, 날씨 · 전파. 인원이 늘면 서버 CPU · 대역폭이 인원 수 이상으로 는다. 플레이어 근처만 정밀하게 돌리고 멀리는 굵게 셈하는 구조(관련성 · AI 세밀도)가 필요하다.
  - **지도가 작다** — 오픈 베타 2 × 4 km 에 100명이면 사냥 · 자원 · 거점 자리가 모자란다. 지도 · 생물 수를 인원에 맞춰야 한다.
  - **운영** — 24시간 서버 비용, 치트 방지(EAC 등), 신고 · 관리 도구, 세이브 백업.
- **권하는 길**(단계): ① 지금: 리슨 서버 최대 8 → ② 전용 서버 16~32(팰월드 수준, 정식 출시 무렵) → ③ 100명은 그 뒤 별도 프로젝트 — 측정(서버 틱 · 대역폭 · 메모리) 결과로 판단. 지금 할 일은 **구조를 100명을 막지 않게 유지**하는 것 하나: 서버 권위 유지, 상태는 휴면 · 근처만 갱신, 세이브는 플레이어 · 세계 분리(이미 그렇게 함).

## 함께 하는 것

- **세계는 하나**: 시간 · 날씨 · 생태계 · 사물의 속성 상태를 모두가 공유한다. 한 사람이 켠 양초를 다른 사람이 바람으로 키울 수 있다(R16).
- **거점 공유**: 파티 공용 거점, 권한은 주인이 관리.
- **던전은 파티 단위 인스턴스**(R12): 함께 들어간 사람끼리만.
- **서클은 개인**: 각자 자기 서클 · 마법 · 그리모어. 마법은 각자 스킬북으로 배운다(필사 없음 — Q5).
- **PvP 없음**(Q13). 넣는다면 출시 뒤 업데이트 스펙으로 따로 다룬다.

## 서버가 쥐는 것

- 진실은 서버에 있다: 전투 · 상태 · 상호작용 · 생태계 · 세이브 모두 서버. 클라이언트는 예측 연출만.
- **세이브**는 서버가 한다. 호스트가 서버를 닫으면 세계가 저장되고, 다시 열면 이어진다.
- 플레이어 데이터(서클 · 마법 · 가방)는 계정별로 저장된다. 다른 서버로 ▢ 가져갈 수 있는지는 미결(Q12).
